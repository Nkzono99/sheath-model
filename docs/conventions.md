# 共通の規約

Fortran・Python のすべての API に共通する単位、座標、符号、成功・失敗の扱いをまとめます。
各 API の文書はこのページを前提にしています。

## 単位と名前

物理量は SI 単位です。例外は温度と法線運動エネルギー（eV）、太陽高度（度）です。
単位は名前の末尾で表します。

| 接尾辞 | 単位 | 例 |
| --- | --- | --- |
| `_v`, `_v_m` | V, V/m | `surface_potential_v`, `plane_field_v_m` |
| `_ev` | eV（温度・法線運動エネルギー） | `electron_temperature_ev`, `energy_edges_ev` |
| `_m3`, `_c_m3` | m⁻³, C/m³ | `ion_density_m3`, `charge_c_m3` |
| `_mps` | m/s | `ion_entry_speed_mps` |
| `_m2_s`, `_a_m2` | m⁻² s⁻¹（数流束）, A/m² | `ion_inward_flux_m2_s`, `net_current_a_m2` |
| `_m`, `_kg`, `_deg` | m, kg, 度 | `z_m`, `ion_mass_kg`, `sun_elevation_deg` |
| `_hat` | 内部の無次元量 | `minimum_field_squared_hat`, Python の `zmax_hat` |

Fortran の実数は `real(dp)`（binary64）、ステータスは `integer(i32)` です。`dp` と `i32` は `use sheath_model` から使えます。

## 座標・電位・符号

| 項目 | 規約 |
| --- | --- |
| 境界 | z=0。単体の解析では電子を放出する表面、結合では matching plane |
| z の向き | +z は境界から上流（プラズマ側）向き |
| 電位の基準 | 上流（z→∞）で 0 V。境界電位 φ_H はこの基準で測る |
| 電場 | `E = -dφ/dz`。境界電場 `E_H` は境界のすぐ上流側の値 |
| 速度 | 上流から境界へ向かう法線速度（電子ドリフト、イオン入口速度）を正とする |
| 数流束 | 名前の向き（`inward`＝境界へ、`outward`・`escape`＝境界から上流へ、`return`＝境界へ戻る）に正 |
| 正味電流 | +z 向きの通常電流 `J = e(Γ_e,in − Γ_i,in − Γ_em,escape)` |

正味電流が正なら、境界へ流れ込む電荷は負です。境界の電荷収支に使う場合は、利用側の符号規約へ換算してください。

## Type A/B/C

解は電位の形で 3 種類に分かれます。φ_min は境界と上流の間を含めた電位の最小値です。

| Type | 電位の形 | φ_H と φ_min | E_H の符号 |
| --- | --- | --- | --- |
| A | 境界と上流の間に電位の極小を持つ | φ_min < min(φ_H, 0)。φ_H は負でもよい | 正 |
| B | 境界から上流へ単調に減少 | φ_H > 0、φ_min = 0（上流） | 0 以上 |
| C | 境界から上流へ単調に増加 | φ_H < 0、φ_min = φ_H（境界） | 0 以下 |

Fortran の `branch` 引数は `'A'`、`'B'`、`'C'`、`'auto'` で、大文字・小文字を区別しません。
Python は `"A"`、`"B"`、`"C"`、`"auto"` のいずれかです。`'auto'` の試行順は各 API の文書に記載しています。
物理的な意味と各 Type の粒子集団は [物理モデル](model.md#電位の形type-abc) を参照してください。

## ステータスとエラー処理

Fortran の手続きは例外を投げず、`status` と `message` を返します。**結果を使う前に必ず `status == SHEATH_OK` を確認してください。**

| 定数 | 値 | 意味 |
| --- | ---: | --- |
| `SHEATH_OK` | 0 | 成功。`message` に探索の補足が入ることがある |
| `SHEATH_INVALID_ARGUMENT` | 1 | 入力・設定・評価点が対応範囲外 |
| `SHEATH_NO_PHYSICAL_SOLUTION` | 2 | 探索した Type・候補が物理条件で除外された。大域的な不存在の証明ではない |
| `SHEATH_NUMERICAL_FAILURE` | 3 | 収束しなかった、または有限値検査・数値積分に失敗した |
| `SHEATH_AMBIGUOUS_SOLUTION` | 4 | 単一解を求めたが、物理解を複数発見した |

失敗時の出力は、結果型なら `valid = .false.`、プロファイルの配列は未確保です。
候補配列は J=0 で長さ 0、E_H 指定で未確保になります（[Fortran API](fortran-api.md#求解メソッド)）。
`message` は `character(len=*)` の引数で、渡した長さで切り詰められます。256 文字以上を推奨します。
[外部解の反復](coupling.md#外部解を更新する) は試した Type ごとの理由を連結するので、512 文字程度を使ってください。

Python は失敗を例外で返します。探索の失敗は `SearchFailure`（診断を `exception.diagnostics` に保持）、
入力の不正は `ValueError` または `TypeError` です。

## 収束・物理解・安定性

ライブラリは次の三つを区別します。

1. **代数方程式の収束**: 準中性・閉じ方（零電流または電場）の残差が許容値以下になった。
2. **物理解**: 収束した根が、上流につながるイオン流体の枝と、実数の電場を持つ半無限プロファイルを持つ（[判定条件](model.md#物理解の判定)）。
3. **動的安定性**: 判定しません。複数の物理解があっても、どれが実現するかは選びません。

返す解は 2 を満たします。探索は有限個の初期値・反復回数で行うため、
失敗・灰色の領域から解の不存在を、候補の一覧から全根の発見を結論できません。

## 状態と副作用

- ライブラリはモジュール変数・`save` 変数を持たず、ファイル出力・標準出力・プロセス終了（`stop`）を行いません。
  状態はすべて呼び出し側が持つオブジェクトにあります。
- `sheath_solver` は数値設定と、明示的に渡した解マップだけを持ちます。求解メソッドは solver を変更せず、前回の解も保持しません。
  物理条件は呼び出しごとに渡します。
- 状態を持つのは [外部解の反復](coupling.md#外部解を更新する) `sheath_matching_iteration` と、呼び出し側が構築する解マップだけです。
- 独立な入力は並列に解けます。[readme_data.f90](../example/readme_data.f90) は OpenMP で格子点を並列に解いています。
- ファイルへの読み書きは、解マップと外部解の `write`/`read` だけで、呼び出し側が開いた unit を使います。
